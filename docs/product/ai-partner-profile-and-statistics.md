# AI 伙伴档案与统计设计

- 状态：持续维护
- 产品名称：AI 伙伴
- 技术资源名：Expert
- 适用范围：组织内伙伴列表、伙伴档案、伙伴统计、市场安装后的伙伴入口

## 1. 目标与边界
Agent Cloud 面向用户提供“AI 伙伴”，而不是暴露一组可复用配置模板。伙伴需要有
稳定身份、明确职责、能力与知识边界、运行治理方式，以及可核验的使用数据。
本设计完成三个目标：
1. 所有用户可见的“专家 / Expert”产品文案改为“伙伴 / AI Partner”。
2. 伙伴详情从配置清单升级为可阅读、可判断、可运行的伙伴档案。
3. 新增组织级伙伴统计页，帮助负责人判断伙伴是否被使用、能力如何分布、哪些档案
   仍需完善。

技术合同保持不变：
- Resource Kind 继续使用 `Expert`。
- REST API 继续使用 `/experts`。
- Rust Core、Go domain 和数据库表继续使用 Expert 命名。
- URL `/{org}/experts/**` 保持兼容；新增统计页使用
  `/{org}/partner-statistics`，避免占用合法伙伴 slug。

## 2. 用户与核心任务
| 用户 | 需要完成的任务 | 关键判断 |
| --- | --- | --- |
| 组织负责人 | 查看所有伙伴的整体使用情况 | 哪些伙伴已投入工作，哪些长期未使用 |
| 伙伴维护者 | 完善伙伴档案和能力配置 | 伙伴职责、能力、知识与治理是否完整 |
| 日常使用者 | 找到并运行合适的伙伴 | 伙伴能做什么、如何工作、是否可运行 |
| 平台审计者 | 判断伙伴来源和控制方式 | 市场安装、资源修订、快照和自动化级别 |

主路径：
```text
伙伴导航
  -> 选择伙伴
  -> 阅读档案与治理边界
  -> 运行或编辑
  -> 查看组织级伙伴统计
  -> 返回需要补充或提升使用率的伙伴
```

## 3. 术语合同
| 层级 | 使用名称 | 说明 |
| --- | --- | --- |
| 用户界面 | 伙伴 / AI Partner | 面向业务目标持续工作的 AI 协作对象 |
| 技术资源 | Expert | 固定 WorkerTemplate、Prompt 与 WorkerSpec 快照 |
| 执行实例 | Worker | 伙伴一次具体运行产生的隔离执行单元 |
| 市场对象 | 伙伴应用 | 可安装、可升级、可审核的伙伴发行物 |

用户界面不得把 Partner、Expert、Agent 和 Worker 混成同一对象。所有面向业务用户
的界面只显示“伙伴”；`Expert` 仅出现在开发者文档、API、代码和资源导出内容中。

## 4. 信息架构
### 4.1 伙伴侧边栏
- 搜索：按伙伴名称和 slug 搜索。
- `伙伴统计`：进入组织级统计页。
- `新建伙伴`：进入现有 Resource-native 创建流程。
- 伙伴列表：显示名称、底层 Agent、已记录启动次数和最近记录时间。
- 空状态：说明组织尚无伙伴，并提供新建入口。
- 错误状态：保留错误信息和重试操作，不能转换为空列表。

### 4.2 伙伴档案
档案按判断顺序组织：
1. **身份**：头像、名称、slug、伙伴类型、职责描述。
2. **工作状态**：已记录启动、最近记录、长期运行、可运行快照。
3. **运行方式**：底层 Agent、交互模式、自动化级别、Runner 与仓库。
4. **能力组合**：Skills、知识库、环境变量包。
5. **工作说明**：分别展示 Prompt 与 AgentFile 约束，缺失时明确标记。
6. **治理与来源**：资源修订、WorkerSpec 快照、市场来源、创建与更新时间。

头像来自伙伴仓库 `metadata.avatar` 指向的文件。加载失败必须显示明确失败状态，
不能静默伪装成“没有头像”。

伙伴类型按来源读取：
- Resource-native Expert：`metadata.category`
- 历史直接创建 Expert：`metadata.expertType`

两条路径是明确的数据合同，不做猜测式兼容。

### 4.3 伙伴统计
第一版统计页为组织级聚合，数据来自完整伙伴列表：
| 指标 | 定义 |
| --- | --- |
| 伙伴总数 | 组织内 Expert 总数 |
| 已记录启动 | 所有伙伴已成功持久化的 `run_count` 之和 |
| 已投入使用 | `run_count > 0` 的伙伴数量 |
| 近 7 日活跃 | `last_run_at` 在最近 7 日内的伙伴数量 |
| 长期运行 | `perpetual = true` 的伙伴数量 |
| 能力覆盖 | 组织内唯一 Skill、Knowledge、Environment Bundle 数量 |
| 档案完整度 | 职责、类型、工作说明、能力、可运行快照五项的完成比例 |
| 运行排行 | 按 `run_count` 降序，最近记录时间作为第二排序条件 |

统计页不展示以下指标，因为当前没有可靠的伙伴级归因合同：
- 成功率与失败率
- Token 与模型成本
- 平均运行时长
- 任务按日、周、月趋势
- 交付物质量评分

这些指标需要不可变的伙伴运行关联、完成状态、用量账本和时间序列接口后再加入。

## 5. 数据合同

前端 `Expert` DTO 与 Rust Core `Expert` 缓存必须无损保留：

- `automation_level`
- `metadata`
- `orchestration_resource_id`
- `orchestration_resource_revision`
- `worker_spec_snapshot_id`
- `source_market_application_id`
- `source_market_release_id`
- `revision`
- Git backing 字段

统计页按首屏 `snapshot_max_id` 边界和不可变 `id DESC` 排序读取全部伙伴：

1. 每页最多 100 条。
2. 按响应 `total` 继续读取。
3. 返回空页但仍未达到 `total` 时明确报错，不能返回部分统计。
4. 后续页固定首屏最大 ID；快照内 `total` 变化时明确报错。
5. 任一页失败时整个统计页进入错误状态。
该边界固定伙伴成员集合，不提供跨请求字段级 MVCC；分页期间已有伙伴字段更新可能来自相邻时间点。

伙伴启动成功但 `RecordRun` 持久化失败时，运行接口返回明确警告；统计页只计算已记录
启动，不把该指标表述成无误差的实际启动总量。

## 6. 视觉与交互

- 继续使用现有 `surface-card`、语义颜色、边框和紧凑排版。
- 统计卡只承载单个指标，不把整个页面包装成大卡片。
- 能力覆盖和使用率使用水平条，动画仅用于数值宽度变化，并尊重
  `prefers-reduced-motion`。
- 档案头部保持工作台密度，主操作为“运行伙伴”，编辑与删除降为次级操作。
- 伙伴统计入口使用图表图标；新建、运行、编辑、删除使用现有 Lucide 图标。
- 桌面与移动端均允许标题和描述换行，不让 slug、按钮或标签遮挡内容。

## 7. 状态与权限

| 状态 | 页面行为 |
| --- | --- |
| 加载中 | 显示稳定尺寸的加载状态 |
| 空组织 | 显示“暂无伙伴”和新建入口 |
| 请求失败 | 显示错误与重试，不展示部分统计 |
| 头像失败 | 显示头像错误标记，档案其余部分继续可读 |
| 无运行记录 | 显示“暂无启动记录”，统计值为 0 |
| 未知自动化级别 | 显示“未知”，不得归入自主运行 |
| Resource-managed | 编辑进入 Validate -> Plan -> Apply 修订流程 |
| Legacy-managed | 编辑使用现有直接配置抽屉 |
| 不可运行 | 缺少 WorkerSpec 快照时运行请求由现有服务明确拒绝 |

## 8. 验收场景

### 场景 A：术语一致

Given 用户进入工作台  
When 查看活动栏、伙伴侧边栏、创建、编辑、运行和市场操作  
Then 用户可见名称为“伙伴 / AI Partner”  
And API 路由、Resource Kind 与代码标识仍为 Expert

### 场景 B：查看伙伴档案

Given 伙伴包含类型、能力、知识、治理和来源数据  
When 用户打开 `/{org}/experts/{slug}`  
Then 页面按身份、运行、能力、工作说明、治理顺序展示真实字段  
And 头像存在时从伙伴仓库读取  
And 页面可进入伙伴统计

### 场景 C：查看伙伴统计

Given 组织有多页伙伴数据  
When 用户打开 `/{org}/partner-statistics`  
Then 页面读取全部分页并展示准确聚合  
And 排行可跳转到对应伙伴档案  
And 不展示无数据合同支撑的成功率、成本或趋势

### 场景 D：失败路径

Given 任一统计分页请求失败或分页停滞  
When 页面加载统计  
Then 页面显示错误和重试  
And 不使用已读取的部分数据生成统计

## 9. 维护规则

出现以下变化时更新本文档：

- Expert DTO、metadata 或资源投影字段变化。
- 伙伴档案新增身份、权限、记忆、目标或协作字段。
- 运行记录建立稳定的 Expert 归因。
- Token、成本、时长、结果状态或质量反馈可按伙伴查询。
- 市场安装、升级或来源合同变化。
- 用户可见产品名称发生变化。

每次更新必须同步检查 Rust Core DTO、TypeScript DTO、i18n、统计口径、浏览器截图
和主要失败状态。
