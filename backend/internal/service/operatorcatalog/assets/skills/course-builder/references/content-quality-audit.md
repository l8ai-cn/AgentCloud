# 内容质量审计标准

用于审计课程学习文件、教师讲授脚本、学生工作纸和任务交付包是否真正可教、可学、可练、可验收。

## 1. 一票否决项

出现任意一项，必须重写：

- 没有具体参考来源。
- 没有真实问题或失败场景。
- “为什么学”没有具体失败样例，只写价值判断或口号。
- 没有回答“为什么学、学什么、怎么做”。
- “怎么做”只有一个动词、一个文件名或一句泛化说明，没有可执行步骤。
- 没有示例、代码、Prompt、配置、命令或数据。
- 代码块只包含文件路径，没有展示文件内容、输入输出、Prompt、JSON、命令或 Trace。
- 没有学生动作。
- 没有提交证据。
- 没有技术引用，或技术引用不能定位到 URL、文件、函数、章节、Notebook 或代码行。
- 没有苏格拉底引导问题。
- 只有教师讲授，没有学生练习。
- 只写“理解、掌握、了解、熟悉”作为目标。
- 只写“完成实验并截图”作为操作。
- 没有错误排查。
- 无法说明本任务与前后章节关系。
- 复杂流程、架构、状态或对比需要图示但没有配图 prompt、alt 文本或资产计划。
- 用户明确要求 image-gen 或课程页面需要最终插图时，没有生成 PNG/JPG/WebP 位图资产。
- 学生可见导航出现 Source Card、Knowledge Card、Evidence Card 等内部研发材料。

## 2. 学习文件审计表

| 项目 | 合格标准 | 评分 |
| --- | --- | --- |
| 来源 | 具体到文件、章节、函数、Notebook 或 URL | 0/1 |
| 问题入口 | 有具体场景和失败样例 | 0/1 |
| 三问定位 | 清楚回答为什么学、学什么、怎么做 | 0/1 |
| 目标 | 3-5 条可观察目标 | 0/1 |
| 引导问题 | 至少 3 个苏格拉底式递进问题 | 0/1 |
| 概念解释 | 先通俗解释，再给工程术语，不是词条堆叠 | 0/1 |
| 技术引用 | 具体到位置，并说明采用点和核查方式 | 0/1 |
| 配图决策 | 需要图时有 prompt/资产/alt，不需要时有理由 | 0/1 |
| 最小示例 | 有 Prompt/代码/配置/命令/数据 | 0/1 |
| 示范过程 | 有操作、现象、解释、排查 | 0/1 |
| 学生练习 | 学生必须改、跑、判、写或交付 | 0/1 |
| 证据 | 明确文件名、数量、格式或日志要求 | 0/1 |
| 错误排查 | 至少 3 个错误及修复动作 | 0/1 |
| 自检题 | 至少 3 题，覆盖概念、操作、失败 | 0/1 |
| 衔接 | 说明前置和后续复用 | 0/1 |
| 饱满度 | 不是表格和文件名堆叠；有失败、反例、示范、练习、rubric 串联 | 0/1 |

评分：

- 13-15：可交付。
- 10-12：可修改后交付。
- 7 及以下：重写。

## 3. 教师讲授脚本审计

教师脚本不能只是“教师讲解”。必须包含：

- 课堂目标；
- 导入问题；
- 板书或屏幕结构；
- 关键提问；
- 苏格拉底式追问链；
- 通俗解释话术；
- 技术引用讲解位置；
- 配图或图示讲解位置；
- 示范步骤；
- 学生即时任务；
- 学生可能误区；
- 反馈话术；
- 课堂检查点；
- 课后衔接。

## 4. 学生工作纸审计

学生工作纸必须能直接填写。至少包含：

- 输入材料；
- 待填写表格；
- 操作记录栏；
- 观察结果栏；
- 失败原因栏；
- 修改计划栏；
- 提交清单；
- 自评问题。

## 5. 提交模板审计

提交模板必须写清楚：

- 文件名；
- 目录结构；
- 每个文件内容；
- 最少样例数量；
- 日志/截图/Trace 要求；
- 脱敏要求；
- 不通过样例；
- rubric。

## 6. 实验需求审计

实验需求单不等于实验 runbook，但必须能交给 `course-lab-builder` 继续落地：

- 实验目标；
- 实验类型；
- 环境和依赖；
- 输入数据；
- 操作摘要；
- 预期输出；
- 证据采集；
- 常见失败；
- 验收方式；
- 平台资源绑定建议。

## 7. 练习需求审计

练习需求单必须能交给 `course-practice-builder` 生成题库：

- 知识点；
- 题型建议；
- 题目目标；
- 正确答案依据；
- 错误选项来源；
- 解析重点；
- 对应学习文件位置；
- quiz 关联建议。

## 8. 语言审计

禁止用空泛语言代替内容：

- “学生理解相关概念”
- “教师介绍背景”
- “完成案例分析”
- “思考如何优化”
- “根据情况调整”
- “参考资料自行阅读”
- “略”
- “怎么做：设计”
- “完成本任务产物”
- “提交运行记录、检查表或报告作为证据”但不说明具体内容

替换为具体动作：

- “学生根据 3 条输出判断哪条 JSON 不能解析，并标注失败字段。”
- “教师演示 `Action: Search[...]` 如何被 `_parse_action` 解析。”
- “学生把 `top_k=2` 改为 `top_k=5`，记录召回文档变化。”

## 9. 饱满度审计

专门检查页面是否像一节完整微课，而不是目录页。

不合格信号：

- 正文主要由表格组成，表格之间缺少解释段落。
- “怎么做”少于 5 个具体步骤。
- 学生看不到一个完整示范，只看到要创建哪些文件。
- 概念解释没有本课例子。
- 没有反例或失败样例。
- 练习没有最少样例数量、通过标准和不通过表现。
- 提交说明没有 rubric。
- 图片只有占位或 SVG/Mermaid，而用户要求 image-gen。

饱满页面应当能让学生回答：

- 我为什么现在要学这个？
- 我照着哪几步能做出来？
- 我做错时应该先查哪里？
- 我交什么能证明会了？
- 这一步会被下一节怎样复用？

## 10. 审计输出格式

每次审计输出：

```markdown
# 质量审计：文件名

## 结论

- 通过 / 修改后通过 / 重写

## 分数

| 项目 | 结果 | 说明 |
| --- | --- | --- |

## 必改问题

1. ...

## 可选优化

1. ...
```
