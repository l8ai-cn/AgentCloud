# 饱满课程研发标准

用于处理用户指出“课程空洞、不像老师备课、学生看不懂、只有文件名和表格”的情况。目标不是把页面写长，而是让学生沿着一条清楚的学习路径完成真实产物。

## 1. 空洞课程的根因

常见根因：

- 只做信息架构，没有做教学展开。
- 只写“为什么学、学什么、怎么做”栏目，没有回答到学生能行动的程度。
- 参考资料只被列名，没有被消化成例子、代码、失败和练习。
- 学习文件被写成任务清单，缺少讲解、示范、反例和排查。
- 审计只检查标题是否存在，没有检查内容密度。
- 教师备课材料直接暴露给学生，学生看到 Source Card 等研发术语。

## 2. 饱满页面的结构

一页合格学习讲义必须像一节微课，按下面顺序展开：

1. 真实任务：本页服务哪个主作品。
2. 失败入口：不学这一步会出现什么具体失败。
3. 旧知连接：学生已有知识如何接上新知识。
4. 概念拆解：每个概念先人话、再术语、再位置、再失败现象。
5. 反例对比：给一个不合格做法，说明为什么不行。
6. 最小示例：展示 Prompt、JSON、代码、命令、Trace 或报告片段。
7. 教师示范：5-8 步，每步有操作、预期现象、解释和排查。
8. 学生练习：学生必须改一个对象、跑一次、判断一次或写一个证据文件。
9. 提交验收：文件名、最少数量、格式、rubric、不通过样例。
10. 迁移衔接：本页产物如何进入下一任务。

## 3. 讲解密度规则

### 3.1 为什么学

必须包含：

- 学生熟悉的场景；
- 一个具体失败样例；
- 失败后果；
- 本页知识如何修复失败。

不合格：

```markdown
为什么学：结构化输出可以减少不稳定。
```

合格：

```markdown
学生输入“RAG 为什么要保留来源”，模型第一次返回一段散文，第二次返回表格，第三次漏掉练习题。
如果程序要把卡片保存进题库，它找不到标题、关键词和练习字段。
所以本页要把“卡片长什么样”写成 schema，再用检查表判断哪张卡片不能被程序消费。
```

### 3.2 学什么

不能只列术语。每个术语要落到主作品。

格式：

```markdown
- schema：不是“格式规范”四个字，而是学习卡片必须有哪些格子，例如 title、keywords、explanation。
- checker：不是老师肉眼看，而是程序或表格逐项检查字段是否存在、类型是否正确。
```

### 3.3 怎么做

必须写成可执行步骤。每一步至少回答：

- 做什么；
- 输入是什么；
- 产出是什么；
- 怎么判断对错；
- 失败先查哪里。

禁止只写：

```markdown
设计 `schemas/card_schema.json`，让 AI 输出 3 张 JSON 卡片，并用 `outputs/format_check.md` 检查。
```

必须展开为：

```markdown
1. 先列出卡片栏目：title、keywords、explanation、example、practice、common_mistake。
2. 给每个栏目写类型：title 是字符串，keywords 是 3-5 个词的数组。
3. 把栏目写进 `schemas/card_schema.json`，不要先追求复杂，只保证程序能检查。
4. 用同一条 Prompt 生成 3 张卡片，保存到 `outputs/cards.jsonl`。
5. 对照 schema 检查字段缺失、类型错误和关键词数量，记录到 `outputs/format_check.md`。
6. 任选一条失败输出，写一条 repair prompt，让模型按失败原因重写。
```

## 4. 概念解释模板

每个核心概念至少 5 句话：

1. 人话解释；
2. 本课小例子；
3. 工程术语；
4. 在哪个文件、Prompt、代码、日志或报告中出现；
5. 做错时会看到什么失败。

示例：

```markdown
schema 可以先理解为“卡片的空格纸”。如果学习卡片规定必须有标题、关键词、解释和练习，schema 就把这些空格写成程序能检查的规则。工程上它通常表现为 JSON Schema、Pydantic Model 或 Output Parser 的字段定义。在本任务里，它放在 `schemas/card_schema.json`。如果 schema 没写清楚，模型可能把 keywords 写成一句话，程序就无法按数组保存。
```

## 5. 示例要求

最小示例必须展示内容，不允许只展示文件名。

合格示例类型：

- 一段 Prompt；
- 一段 JSON；
- 一段 Python 函数；
- 一条命令和输出；
- 一条 Trace；
- 一份报告片段；
- 一个失败输入和失败输出。

不合格代码块：

```text
schemas/card_schema.json
outputs/format_check.md
```

## 6. 学生可见页面与内部备课材料

学生可见页面：

- 学习讲义；
- 实操任务；
- 课堂练习；
- 提交说明；
- 测验或实验入口。

内部备课材料不得出现在学生导航：

- Source Card；
- Knowledge Card；
- Evidence Card；
- Pedagogy Card；
- Technical Citation Card；
- Visual Asset Card；
- Quality Audit。

这些卡用于研发，不用于学生直接阅读。

## 7. 配图要求

配图不是装饰，必须降低理解成本。

需要配图的情况：

- 组件关系超过 3 个；
- 流程超过 4 步；
- 有状态、分支、回退；
- 有对比、边界、错误排查。

课程封面、课程插图、用户明确要求 image-gen 时，必须使用 `imagegen` 生成 PNG/JPG/WebP 位图，并把最终图片复制到课程仓库。Mermaid/SVG 只能用于用户明确允许的确定性工程图，不能替代 image-gen 产物。

## 8. 饱满度审计清单

任意一项为否，先重写，不发布：

- 学生能说出本页服务哪个主作品吗？
- 有具体失败样例吗？
- 术语是否有“人话解释 + 本课例子 + 工程位置 + 失败现象”？
- “怎么做”是否展开为 5-8 步？
- 示例是否展示真实内容，而不是文件路径？
- 学生是否需要改、跑、判、写或交？
- 提交物是否有数量、格式、rubric 和不通过样例？
- 需要图的地方是否有 imagegen 图片资产？
- 内部研发卡是否没有暴露给学生？
