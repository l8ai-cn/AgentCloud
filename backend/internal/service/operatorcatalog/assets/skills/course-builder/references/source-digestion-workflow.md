# 参考资料消化工作流

用于把 GitHub 课程、文档站、Notebook、代码仓库、论文或实验项目转化为课程知识点。禁止只把资料名称放进课程正文。

## 1. 消化原则

参考资料不能直接搬运，也不能只列链接。必须拆成：

- 概念：它定义了什么；
- 代码：它如何实现；
- 样例：它用什么输入输出说明；
- 实验：它让学生运行什么；
- 失败：它暴露什么常见错误；
- 评估：它如何判断好坏；
- 迁移：它能放到本课哪一个任务。

## 2. 资料读取顺序

1. 先读目录和 README，判断资料定位。
2. 再读与本章相关的 1-3 个核心文件，不要泛读全仓库。
3. 如果有代码，定位类、函数、命令、Notebook cell。
4. 如果有实验，定位环境、输入、运行方式、输出证据。
5. 如果有习题，拆成练习或 quiz 素材。
6. 输出 source-card，不进入正文前不得跳过。

## 2.1 Evidence Policy

资料消化以证据质量为准，不以调研次数为准。固定次数只能作为成本提示，不能作为硬性退出条件。任何未被证据支撑的内容都不能写成确定结论。

证据分级：

- `A 级证据`：官方文档、源代码、Notebook 输出、平台 API 回读、可运行实验、测试结果、课程原始素材。
- `B 级证据`：可信技术文章、项目 README、示例仓库、历史课程成品、教师说明。
- `C 级证据`：模型推断、常识性经验、未验证二手资料、缺上下文片段。

使用规则：

- 核心机制、操作步骤、实验验收、评分标准必须有 A/B 级证据。
- C 级证据只能写为假设、待确认项或辅助解释。
- 证据不足时，先收窄到具体文件、函数、配置、命令、接口、Notebook cell、日志或实验输出。
- 如果换用本地仓库、平台 API、官方文档、测试用例、实验结果后仍不足，必须在 source-card 中标明缺口、替代依据、可信等级、教学风险和补证路径。
- 只要学生仍能完成明确动作并提交可验收证据，可以继续交付已确认部分；否则输出资料需求单、实验需求单或 `blocked` 状态。

停止条件：

- 缺口会导致学生无法操作或无法验收。
- 核心结论只能靠猜测。
- 可能让学生学到错误内容。
- 涉及安全、合规、账号、密钥、生产环境或用户数据风险。

## 3. Source Card 模板

| 字段 | 内容 |
| --- | --- |
| 来源名称 | 课程/仓库/文档/论文名称 |
| 来源位置 | 文件路径、章节、函数、Notebook cell 或 URL |
| 原始要点 | 原资料真正讲了什么 |
| 可用代码 | 类、函数、命令、Prompt、配置 |
| 可用例子 | 输入、输出、场景 |
| 可用失败 | 错误、局限、调试点 |
| 可用练习 | 可改写成学生任务或 quiz 的素材 |
| 课程去向 | 第几章、第几个任务、第几个学习文件 |
| 采用方式 | 引用、改写、仿照、对比、实验复现 |

## 4. Knowledge Card 模板

| 字段 | 内容 |
| --- | --- |
| 知识点 | 一个最小知识点 |
| 解决问题 | 不学会出现什么失败 |
| 前置知识 | 学生已学什么才能进入 |
| 核心机制 | 用 3-5 句话讲清楚 |
| 本课例子 | 用哪个 Prompt/代码/数据承载 |
| 学生动作 | 修改、运行、判断、解释、对比或构建 |
| 输出证据 | 学生交什么 |
| 常见失败 | 至少 2 个 |
| 后续复用 | 下一任务如何复用 |

## 5. Evidence Card 模板

| 字段 | 内容 |
| --- | --- |
| 产物名称 | 文件、报告、日志、Trace、截图、JSON |
| 最小要求 | 数量、字段、运行结果或格式 |
| 验收方法 | 教师如何检查 |
| 失败样例 | 什么情况判不通过 |
| 对应题目 | 进入练习/quiz 的考点 |

## 6. 代码参考的处理方式

如果参考资料有代码，学习文件必须回答：

- 入口文件是什么；
- 关键函数/类是什么；
- 输入参数是什么；
- 中间状态是什么；
- 输出是什么；
- 学生需要改哪里；
- 改完如何验证；
- 失败时看哪个日志、异常或 Trace。

## 7. Notebook 参考的处理方式

如果参考资料是 Notebook，学习文件必须指出：

- 哪几个 cell 是核心；
- cell 的输入输出是什么；
- 哪些变量要保留；
- 哪些代码需要改写成课程脚本；
- 哪些输出截图或结果要提交；
- 哪些 cell 不适合直接用于课程。

## 8. 多参考资料整合

多个参考资料必须分主次：

- 主干资料：决定本任务的教学路径。
- 支撑资料：补概念、API 或示例。
- 对照资料：说明另一种做法或边界。
- 实验资料：提供可运行环境或项目。

不要把多个资料并列堆进同一页。学习文件最多使用 1 个主参考和 1-2 个支撑参考。

## 9. 不合格信号

- 写“参考 hello-agents”但没有文件路径。
- 写“参考 LLM Cookbook”但没有对应章节。
- 写“参考代码实现”但没有类、函数或命令。
- 只总结资料讲了什么，没有说明学生做什么。
- 只拿术语，没有拿例子、代码或失败。
- 没有说明参考资料如何进入实验、练习或 quiz。
