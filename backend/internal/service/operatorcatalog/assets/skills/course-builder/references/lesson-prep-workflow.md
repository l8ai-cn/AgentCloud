# 章节备课工作流

用于把一章课程从“大纲标题”研发成可教学任务。核心原则：先设计学生最终能做什么和交什么证据，再安排讲解、示范、练习、反馈和必要图示。

## 1. 教学设计依据

本工作流综合使用以下稳定框架：

- Backward Design：先确定学习目标，再确定可接受证据，最后设计学习活动。
- Constructive Alignment：学习目标、教学活动、评估任务必须逻辑对齐。
- Gagne 九事件：吸引注意、说明目标、激活旧知、呈现内容、提供指导、引发表现、反馈、评估、迁移保持。
- Merrill 首要教学原理：围绕真实任务，激活旧知，示范新知，应用练习，整合迁移。
- Bloom 修订分类：学习目标要用可观察动词，避免只写“理解、掌握、了解”。
- ADDIE：分析、设计、开发、实施、评价；本 skill 主要覆盖分析、设计、开发和形成性评价。
- Socratic Questioning：提前设计清晰、具体、开放的追问，让学生观察、解释、举证、判断边界。
- Plain Language：术语首次出现时必须先用学生语言解释，再给工程术语。
- UDL：用文字、表格、示例、图示、操作和反思为不同基础学生提供入口。
- Mayer 多媒体原则：图示只服务学习目标，去除无关装饰，文字和图互补。

## 2. 备课总流程

每章必须先完成 12 个备课环节。

| 环节 | 必答问题 | 产物 |
| --- | --- | --- |
| 学情分析 | 学生已经会什么？最可能卡在哪里？不能假设什么？ | `learner-profile` |
| 章节定位 | 本章在整门课能力链中负责哪一段？ | `chapter-position` |
| 三问定位 | 学生为什么学、学什么、怎么做？ | `why-what-how` |
| 学习目标 | 学生学完能做哪些可观察动作？ | `learning-outcomes` |
| 验收证据 | 学生交什么能证明学会了？ | `evidence-plan` |
| 对齐检查 | 目标、活动、练习、测验是否一一对应？ | `alignment-map` |
| 参考消化 | 哪些参考文件、代码、Notebook 真正会用？ | `source-map` |
| 技术引用 | 技术依据具体到 URL、文件、函数、章节或代码行了吗？ | `technical-citations` |
| 知识点拆分 | 本章有哪些最小知识点？先后关系是什么？ | `knowledge-map` |
| 案例选择 | 用哪个真实问题承载知识点？ | `anchor-case` |
| 引导问题 | 哪些问题让学生先观察、解释、举证和迁移？ | `socratic-question-list` |
| 通俗讲解 | 每个术语如何先说人话、再给工程名？ | `plain-language-note` |
| 教学流程 | 如何从问题进入，示范，再让学生练？ | `lesson-flow` |
| 配图设计 | 哪些流程、架构、状态或对比需要图示？prompt 和资产路径是什么？ | `visual-asset-plan` |
| 实操设计 | 学生运行、修改、观察什么？ | `lab-requirement` |
| 练习设计 | 哪些概念、操作、失败要进入练习/quiz？ | `practice-requirement` |
| 反馈机制 | 学生如何获得即时反馈和修正路径？ | `feedback-plan` |
| 章节衔接 | 本章产物如何进入下一章？ | `transfer-note` |

## 3. 章节目标写法

目标必须是“学生 + 动词 + 对象 + 条件/标准”。

合格：

- 学生能根据 3 条模型输出判断哪条不能被 JSON parser 解析，并说明失败原因。
- 学生能把自由问答 Prompt 改写成包含角色、输入、输出 schema、约束和失败处理的结构化 Prompt。
- 学生能运行 ReAct Agent 的一次完整轨迹，并标注 Thought、Action、Observation、Finish 四类事件。

不合格：

- 理解 Prompt 工程。
- 掌握 Agent 原理。
- 熟悉 LangChain。

## 4. 章节任务拆分

每章 3-6 个任务。任务不是小节标题，而是学生能完成的动作。

任务命名格式：

`动词 + 对象 + 产物`

示例：

- 设计结构化 Prompt 与输出检查。
- 封装 PromptTemplate 与 Output Parser。
- 实现 ReAct 工具调用轨迹。
- 比较相似性检索、MMR 和 metadata 过滤。
- 构建带评估集的知识库问答 Agent。

每个任务必须有：

- 主知识点；
- 学生动作；
- 输入材料；
- 产物；
- 验收证据；
- 对应课件；
- 对应实验需求；
- 对应练习/quiz 需求。
- 方法论说明：为什么这个任务放在这里，如何承接上一任务并支撑下一任务。
- 苏格拉底引导问题：至少 3 个。
- 通俗解释策略：关键术语的人话解释和失败现象。
- 技术引用：具体到来源位置。
- 配图决策：需要图时有 prompt 和资产；不需要时说明理由。

## 5. 教学流程模板

每个任务的教学流程使用：

1. 问题入口：给一个具体失败或业务需求。
2. 激活旧知：连接上一章已经做过的东西。
3. 概念解释：只讲完成任务所需的概念。
4. 苏格拉底提问：让学生观察现象、解释原因、拿证据、判断边界。
5. 通俗讲解：先说人话和小例子，再给工程术语。
6. 教师示范：展示 Prompt、代码、配置、Trace、报告或图示。
7. 学生操作：学生改一个参数、补一个函数、跑一条路径或判断一次失败。
8. 反馈检查：用日志、parser、测试、rubric 或同伴检查给反馈。
9. 迁移应用：说明这个知识点在下一任务或综合实践中如何复用。

## 6. 章节交付单

每章结束必须生成 `chapter-XX-delivery.md`，包含：

- 本章任务清单；
- 每个任务的学习文件、教师脚本、学生工作纸、提交模板路径；
- 实验需求单路径；
- 练习需求单路径；
- 题库/quiz 待绑定点；
- 技术引用清单；
- 配图清单：图片 prompt、资产路径、alt 文本；
- 本章主产物；
- 学生提交清单；
- 质量审计结论；
- 下一章复用说明。

## 7. 备课质量门

章节备课不合格的信号：

- 只有章节标题，没有学生产物。
- 只有概念列表，没有先后依赖。
- 只引用资料名，没有具体文件和代码。
- 学习目标无法观察。
- 任务无法交付证据。
- 教学活动只有教师讲，没有学生做。
- 练习和题库没有对应知识点。
- 本章产物无法衔接下一章。
- 没有回答学生为什么学、学什么、怎么做。
- 没有苏格拉底引导问题。
- 术语没有通俗解释。
- 技术引用只写资料名，没有位置。
- 复杂流程、架构或状态变化没有图示，也没有说明不配图的理由。
